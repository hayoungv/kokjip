# 원가 모형

> S4(전사와 판정에 쓰는 외부 서비스, 원가 상한)를 정하기 위해 계산한 자료다.
> 이 계산에서 나온 두 가지 발견이 S10을 새로 세우고 T4를 다시 열게 했다.

---

## 1. 원가가 붙는 경로

분량에 비례해 돈이 나가는 곳은 두 군데다. 나머지는 반올림하면 사라진다.

| 경로 | 과금 방식 | 크기 |
|---|---|---|
| 음성을 글로 옮기기 | 녹음 길이 1시간당 | 지배적 |
| 강조한 말 찾기 | 글자 수를 토큰으로 환산해 100만 토큰당 | 두 번째 |
| 강의 기록 저장 | 용량당 | 한 기수 6개월치가 수 메가바이트 |
| 음성 경유 | 전송량과 임시 저장 | 처리 직후 지우므로 작다 |

## 2. 계산에 쓴 값

| 값 | 수치 | 출처 |
|---|---|---|
| 강의 1시간당 글자 수 | 18,495자 | 선행 실측 전사 원문 6시간 7분에서 113,193자를 직접 셈 |
| 월 강의 시간 | 약 160시간 | 6개월 과정 기준 |
| 음성을 글로 옮기는 단가 | 시간당 0.258달러 | 관리형 서비스 중 가장 낮은 수준 |
| 강조한 말 찾는 단가 | 입력 100만 토큰당 5달러, 출력 25달러. 묶음으로 보내면 절반이다 | 확정 스택의 `claude-opus-5` 기준 (S7) |
| 환율 | 1달러 1,450원 | 가정 |
| 글자를 토큰으로 바꾸는 비율 | 1자당 1.2토큰 | **추정값. 실제 측정으로 확인해야 한다** |

## 3. 발견 1 — 학습자마다 전사하면 제품이 성립하지 않는다

PRD는 학습자가 각자 녹음해 올린다고 정했다. 그대로 두면 정원 30명 기수에서 같은 6시간 강의를 30벌 전사하게 된다.

| 방식 | 월 전사 대상 | 월 전사비 |
|---|---|---|
| 학습자마다 전사 | 4,800시간 | 약 180만 원 |
| 회차당 한 벌만 전사 | 160시간 | 약 6만 원 |

매출이 월 9만 원인데 원가가 180만 원이다. 회차당 한 벌만 전사하는 것은 선택이 아니라 제품이 성립하기 위한 조건이다.

**앞선 결정이 이것을 가능하게 해 둔다.** 앱이 직접 녹음하므로 녹음을 시작한 절대 시각을 안다. 한 벌만 전사해 얻은 발화 지점을 절대 시각으로 바꾸면, 각 학습자의 녹음에서 그 지점이 몇 분 몇 초인지 환산할 수 있다. 다시 듣기는 각자 자기 기기의 원본으로 그대로 한다.

## 4. 발견 2 — 1인 월 3,000원은 원가를 덮지 못한다

회차당 한 벌만 전사해도 그렇다. 정원 30명 기수 기준이다.

| 항목 | 계산 | 월 비용 |
|---|---|---|
| 음성을 글로 옮기기 | 160시간 × 0.258달러 | 약 60,000원 |
| 강조한 말 찾기 (입력) | 약 355만 토큰 × 5달러 × 절반 | 약 12,900원 |
| 강조한 말 찾기 (출력) | 약 18만 토큰 × 25달러 × 절반 | 약 3,300원 |
| **합계** | | **약 76,200원** |

매출은 30명 × 3,000원 = 90,000원이다. 원가율 85%이고 서버비와 개발비와 이익이 들어갈 자리가 없다.

원가가 기수 단위라 정원이 작을수록 나빠진다.

| 기수 정원 | 1인당 원가 | 1인당 3,000원 받을 때 |
|---|---|---|
| 20명 | 3,810원 | 적자 |
| 30명 | 2,540원 | 460원 남음 |
| 40명 | 1,905원 | 1,095원 남음 |

정원 20명대 기수는 팔수록 손해다.

## 5. 확인이 필요한 값

- 글자를 토큰으로 바꾸는 비율. 1자당 1.2토큰은 추정값이며, 실제 전사 원문으로 토큰 수를 세어 확인해야 한다.
- 음성을 글로 옮기는 서비스의 한국어 정확도. 단가만 보고 고를 수 없다.
- 환율 1,450원. 원가가 외화로 발생하므로 환율이 원가율을 직접 흔든다.

## 10. 학습 자료에서 목차를 읽는 비용

과정 하나에 한 번 드는 비용이다. 매일 도는 판정과 달리 한 번만 든다.

| 형식 | 입력 토큰 | 비용 |
|---|---:|---:|
| 목차 쪽만 골라 넣기 (3쪽) | 2,880 | 130원 |
| 글자가 든 파일 전체 (50쪽) | 48,000 | 457원 |
| 글자가 든 파일 전체 (100쪽) | 96,000 | 805원 |
| 공개된 웹 페이지 (글 20,000자) | 24,000 | 283원 |
| 책 목차 사진 (5장) | 8,000 | 167원 |
| 스캔한 파일 (100쪽 사진) | 160,000 | 1,269원 |
| 스캔한 파일 (300쪽 사진) | 480,000 | 3,589원 |

계산에 쓴 값은 한 쪽 800자, 글자당 1.2토큰, 사진 한 장 1,600토큰, 내는 목차 3,000토큰이다. 목차 읽기는 강사가 화면 앞에서 기다리므로 묶음으로 보내지 않는다. 낱개 단가로 셈했다.

### 한 사람당 부담

가장 비싼 경우인 300쪽 스캔 파일을 기준으로 봐도 이렇다.

| 기수 정원 | 1인당 | 6개월 과정에서 월 | 원가 상한 대비 |
|---|---:|---:|---:|
| 20명 | 179원 | 30원 | 3.0% |
| 30명 | 120원 | 20원 | 2.0% |
| 40명 | 90원 | 15원 | 1.5% |

### 읽히는 것

**형식을 넓혀도 비용이 걸림돌이 아니다.** 비용이 갈리는 지점은 글자가 들어 있는 파일이냐 사진이냐이고, 사진이 비싸긴 하나 절대 금액이 작다.

**쪽수가 많을 때는 목차가 있는 쪽만 받는다.** 3쪽과 100쪽이 여섯 배 차이가 나는데, 강사에게 물을 것은 몇 쪽에 목차가 있는지 하나뿐이다.

## 11. 두 번 나눠 도는 판정이 더하는 비용

말을 목차 항목에 붙이려면 그 회차가 다룬 목차 구간을 먼저 정해야 한다. 이 처리에 강의 기록이 한 벌 더 들어간다.

기준은 4장과 같다. 정원 30명 기수, 강조한 말 찾기 입력이 월 355만 토큰, 입력 100만 토큰당 5달러이며 묶음으로 보내 절반이 든다. 앱이 기기에서 전사하므로 음성을 글로 옮기는 값은 들지 않는다.

| 항목 | 월 비용 (기수 전체) |
|---|---:|
| 말 찾기 (입력) | 12,900원 |
| 말 찾기 (출력) | 3,300원 |
| 구간 정하기 (입력, 솎지 않음) | 12,900원 |
| 구간 정하기 (입력, 넷 중 하나) | 3,200원 |

구간 정하기가 내는 것은 목차 항목 번호 몇 개라 출력 값은 셈에 넣지 않아도 될 만큼 작다.

### 1인당 부담

| 솎는 비율 | 정원 30명 | 정원 20명 |
|---|---:|---:|
| 구간 정하기 없음 | 540원 | 810원 |
| 솎지 않는다 | 970원 | 1,460원 |
| 넷 중 하나를 넣는다 | 650원 | 970원 |

원가 상한은 1인 월 1,000원이다. **솎지 않으면 정원 20명 기수에서 상한을 넘는다.** 원가가 기수 단위로 들어 정원이 작을수록 1인당 부담이 커지기 때문이다.

그래서 솎는 비율의 초기값을 넷 중 하나로 둔다. 회차가 어느 장을 다뤘는지 가리는 데에 모든 문장이 필요하지 않다. 솎는 비율은 판정 품질을 재며 조정한다.

### 목차를 다시 이을 때

과정 중간에 학습 자료를 바꾸면 그 과정의 회차를 다시 이어야 한다. 강의 기록은 그대로 있으므로 다시 전사하지 않지만 판정은 다시 돈다. 그달의 판정 값이 한 번 더 드는 셈이다. 강사가 자료를 바꾸는 일이 잦지 않아 막지 않는다.
