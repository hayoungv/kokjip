# KOKJIP 포트폴리오 결과 요약 — 강의 복습 우선순위 서비스 가설 검증

> **문서 목적:** 포트폴리오용 결과 요약 (문제 → 탐색 → 검증 → 판단 → 실행 → 결과 → 한계)
> **기준 시점:** 2026년 9월
> **대상 범위:** 챕터 00~08 + 부록 A + Signal Classifier v0.1 / v0.2 실측
> **작성 원칙:** 이 문서의 모든 수치는 저장소 내 원자료에서 재계산해 확인한 값만 기재한다. 확인되지 않은 성과는 적지 않는다.
> **근거 표기:** 🟢 실측·사실 · 🟡 추론 · 🔴 미검증 가설

---

## 1. 문제

국비 부트캠프 수강생에게 "복습 시간 부족"과 "무엇을 버릴지 선별하는 어려움"은 실재하는 문제로 확인됐다. 그러나 **문제가 실재한다는 것과 사업이 성립한다는 것은 다른 문제**였다.

챕터 00~08 분석 끝에 도출된 코어 가치는 다음과 같다.

> AI의 자의적 요약이 아니라, **강사의 구어체 실무 강조 발화(Provenance)를 근거로** 복습 우선순위를 제시하고 원천 오디오로 즉시 연결한다.

이 가치는 단 하나의 전제 위에 서 있었다 — **강사가 그런 발화를 실제로 충분히 자주 하는가.**

전제가 무너지면 VPS의 코어 가치 전체가 붕괴하고, 04~07 챕터(시장 규모·페르소나·기회점수·JTBD)가 전제한 문제 정의까지 함께 무효가 되는 의존 구조였다.

---

## 2. 탐색

### 세운 기준 ①  주장마다 근거 등급을 매기고, 등급이 낮으면 진도를 막는다

최종 산출물의 핵심 가치 주장 11개를 Grounding Matrix로 등급화했다.

| 등급 | 내용 | 개수 |
|---|---|:---:|
| 🟢 실측·사실 | 경쟁 8개사 중 '버릴 것을 정해주기'를 선언한 곳 **0** · 무료 번들로 단순 전사·요약의 시장 가격 **0원 수렴** | 3 |
| 🟡 추론 | 결핍 점수 1위(AOS 3.00 / DOS 3.00) · 비전공자 권위 의존 심리 · UI 구조 분석 | 4 |
| 🔴 미검증 | 신호 밀도 · 신뢰 채택 · 유료 전환 · 기관 예산 | **4** |

핵심은 등급을 매긴 것이 아니라 **매긴 결과에 따라 행동을 바꾼 것**이다.

> **1~7은 제품을 설계할 수 있게 하고, 8~11은 제품을 만들어도 되는지를 정한다.**
> 8~11이 전부 🔴이므로 **PRD 작성이 동결돼 있다.**

기능 정의를 더 하고 싶은 유혹을 규칙으로 막은 것이 이 단계의 실제 산출물이다.

### 왜 이 가치였는가

경쟁 8개사 실사 결과 '버릴 것을 정해주기'를 선언한 사업자는 없었고(🟢), 단순 전사·요약은 빅테크 무료 번들로 가격이 0원에 수렴했다(🟢). 남은 차별화 경로는 **출처(Provenance)** 하나였다.

## 3. 검증

### 세운 기준 ②  측정하기 전에 합격선을 먼저 적어둔다

🔴 네 개 중 가장 값싸고 가장 결정적인 **H-Signal**을 게이트 1번으로 놓고, **실험을 돌리기 전에** 판정 기준을 문서에 고정했다.

| 결과 | 판정 |
|---|---|
| 시간당 평균 **≥ 2.0회** | 가치 B 확정 |
| 시간당 평균 0.5 ~ 1.9회 | 신호 정의 범위 조정 |
| 시간당 평균 **≤ 0.2회** | 가치 B 기각 → 채용공고 축으로 전면 피벗 |

임계값 옆에 다음 단서를 함께 명시했다.

> ※ 이 임계값은 시장 통계나 확정 KPI가 아니라 **가설 유효성 판단을 위해 설정한 실험용 값**이다.

결과를 보고 나서 기준을 움직이지 못하게 하려는 장치였다.

### 실측 절차

실제 KDT 강의 STT **2일치 · 4개 세션 · 6시간 07분**으로 진행했다.

| 세션 | 길이 |
|---|---|
| 26일 1교시 | 1:38:06 |
| 26일 2교시 | 2:05:10 |
| 26일 3교시 | 0:46:14 |
| 27일 | 1:37:33 |
| **합계** | **6:07:03** |

1. **Signal Dataset v0.1** — 사람이 신호 후보 68건을 구조화
2. **Classifier Prompt v0.1** — 분류 규칙을 프롬프트로 명문화하고, 후보와 독립적으로 AI가 전 구간 재판정 → 신규 43건 추가 발견(총 111건)
3. **Human Review** — 111건 전건을 사람이 Y/N · Type · 강도로 재판정 → **53건 확정**

### 세운 기준 ③  유리한 분모를 쓰지 않는다

신호 밀도를 네 가지 분모로 모두 계산해 병기하고, 최종 판정은 **가장 보수적인 값**으로 했다.

| 분자 | 분모 | 밀도 |
|---|---|---|
| v0.1 판정 106건 | 업로드 STT 전체 6.12h | 17.3 회/h |
| v0.2 판정 74건 | 업로드 STT 전체 6.12h | 12.1 회/h |
| **사람 확정 53건** | **업로드 STT 전체 6.12h** | **8.7 회/h** |

AI가 찾은 106건이 아니라 사람이 확정한 53건만 분자로, 태깅 구간이 아니라 업로드 STT 전체를 분모로 써도 **8.7회/h — 게이트 2.0회/h의 4.3배**다. 게이트 통과에 필요한 최소 신호 수는 13건이었고, 실제 확정은 53건이었다.

**네 가지 분모 어느 것으로 계산해도 게이트를 통과했다.**

## 4. 판단

### 게이트는 통과했다. 그런데 통과한 것은 두 질문 중 하나뿐이었다

실측 결과를 정리하면서, 섞여 있던 두 질문을 분리했다.

| 질문 | 결과 |
|---|---|
| **신호가 존재하는가** | 🟢 게이트 통과 (8.7 ~ 17.3회/h, 임계 2.0회/h) |
| **AI가 그 신호를 안정적으로 뽑는가** | 🔴 **별개의 문제이고, 통과하지 못했다** |

v0.1 분류기를 사람 판정과 대조한 결과는 다음과 같았다.

- **Precision 48.1%** — 111건 중 106건을 Signal로 판정했으나 사람이 인정한 것은 53건
- **Type 일치율 45.1%** — 같은 발화를 Signal로 본 건에서도 유형 판단이 절반 이상 어긋남

즉 **"신호는 분명히 있지만, 현재 분류 규칙은 신호와 수업 진행 멘트를 구분하지 못한다."**

### 결론에 유리하지 않은 사실을 함께 기록

v0.1 실행 보고서에 「이 결과가 말하지 않는 것」 항목을 따로 만들어 명시했다.

- 강사 1인·2일치 표본이므로 KDT 전반의 신호 밀도가 아니라 **이 강사의 신호 밀도**다
- Human Candidate가 확정 Ground Truth가 아니므로 **Precision/Recall을 성능 지표로 확정하지 않는다**
- 신호가 존재한다는 것과 AI가 안정적으로 추출한다는 것은 **별개**이며, 후자는 독립 평가셋이 필요하다
- 업로드 STT 총 길이(6시간 07분)와 사전에 제시된 3시간 43분이 **일치하지 않는다 — 분모 확정 필요**

마지막 항목은 결론에 유리하지 않은 불일치였지만 덮지 않고 기록했고, **이후 추적해 해소했다.** 3시간 43분은 26일 1교시(1:38:06)와 2교시(2:05:10)의 합계 **3:43:16**으로, 26일 3교시와 27일 STT를 추가하기 전 시점의 값이었다. 분석 누락이 아니라 값 미갱신이었고 **확정 분모는 6시간 07분**이다. 어느 분모로 계산해도 게이트는 통과한다(53건 ÷ 3.72h = 14.2회/h · 53건 ÷ 6.12h = 8.7회/h).

## 5. 실행

### 세운 기준 ④  오류를 세지 말고, 오류의 원인을 규칙으로 고친다

v0.1의 오분류를 유형별로 진단한 뒤, 각 진단에 1:1로 대응하는 규칙을 넣어 **Classifier Prompt v0.2**를 작성했다.

| 진단된 실패 | v0.2에 넣은 규칙 |
|---|---|
| "이 수업에서만 통하는 조작 지시"를 신호로 셈 | **G1 이전 가능성 게이트** 신설 — 다른 프로젝트에 옮겨 적을 수 있는가를 먼저 묻는다 |
| "단어가 아닌 기능으로 판단하라"면서 판정 기준은 단어 목록을 줌 (자기모순) | Type 판별을 **기능 판별 질문**으로 교체 |
| 한국어 `~해야 돼요`를 전부 MUST로 흡수 | **당위 어미·강조 부사 전처리** 후 판정 |
| 강도가 한 방향으로만 과대 산정됨 | **기본값 2 + 승격 조건 명문화** |
| 앵커가 항상 뒤로 밀려 판정까지 오염 | 근거가 **시작되는** 블록에 timestamp |
| 경계 사례를 임의로 하나 고름 | **애매 사례 강제 판정 금지** — 후보 병기 + 사유 기록 |

### 세운 기준 ⑤  재채점은 눈을 가리고 한다

- v0.2 재분류는 STT 원문에서 앵커 앞 3블록 · 뒤 4블록을 잘라내되, **v0.1 Type·강도와 Human 판단 컬럼을 제거한 문맥 파일**로 수행했다
- 정답 대조는 **채점 단계에서만** 했다
- 두 버전에 **동일한 지표 정의**를 적용했다 — TP/FP/FN/TN 정의 동일, Type·강도 일치율의 **분모는 TP**(둘 다 Signal로 본 건)로 통일

## 6. 결과

### 네 지표 중 셋이 올랐고, 재현율만 내려갔다

| | Precision | Recall | Type 일치율 | 강도 일치율 |
|---|---|---|---|---|
| v0.1 | 48.1% | **96.2%** | 45.1% (23/51) | 62.7% (32/51) |
| **v0.2** | **63.5%** | 88.7% | **63.8%** (30/47) | **76.6%** (36/47) |

TP/FP/FN/TN: v0.1 `51 / 55 / 2 / 3` → v0.2 `47 / 27 / 6 / 31`

### 줄어든 오탐은 무작위가 아니라 새로 넣은 규칙에 대응했다

- **MUST 33건 → 7건** (사람 정답 7건). 어미 전처리가 의도한 그대로 작동했고, 반대급부로 v0.1이 구조적으로 못 잡던 **EMPHASIS가 1건 → 11건**(정답 9건)이 됐다
- **INSIGHT 11건 → 0건, REVIEW 4건 → 0건** (사람 정답 둘 다 0건). v0.2가 제외 예시로 직접 써 둔 두 발화가 실제로 v0.1에서 INSIGHT/강도3으로 올라가 있었다
- **G1 게이트**가 `꼭`·`반드시`가 붙은 개별 조작 지시 3건을 걸러냈다. v0.2가 *"강한 지시어는 오히려 개별 조작 지시에서 더 자주 나타난다"*고 경고한 패턴이 그대로 재현됐다
- 새로 넣은 **입력 검증이 실제로 발동**했다 — 다음 블록 완화 3건, STT 극성 오인식 1건(앞 블록은 권장인데 해당 블록만 금지문)

### 강도 편향은 제거됐지만, 보정이 목표를 지나쳤다

| | 과대 산정 | 과소 산정 |
|---|:---:|:---:|
| v0.1 | 18 | 1 |
| v0.2 | **0** | **11** |

한 방향 편향은 사라졌으나 반대 방향으로 기울었다. 이것도 결과에 그대로 기록했다.

### 대가는 명확했다

Recall 96.2% → 88.7%, FN 2건 → 6건. **정밀도를 사고 재현율을 판 것이고, 같은 조정의 양면이다.** 어느 쪽이 더 비싼 오류인지는 제품이 오탐과 미탐 중 무엇을 더 감당할 수 있는가에 달려 있고, 이 표본만으로는 결정되지 않는다.

## 7. 한계 및 다음 실험

> **지표를 올린 것보다, 이 지표가 무엇을 증명하지 못하는지를 아는 것이 이 프로젝트의 결과에 가깝다.**

### 측정 자체의 한계

- 사전 설계는 **녹취 3~5개 · 15~25시간**이었으나 실제 실측은 **6시간 07분**이었다. 게이트는 통과했지만 **설계된 규모에는 미달**했다
- 표본은 **강사 1인 · 2일치**다. KDT 전반이 아니라 이 강사의 신호 밀도다
- 평가 대상 111건은 **v0.1이 만든 후보 풀**이다. v0.1이 아예 찾지 못한 발화는 표본에 없으므로 두 버전의 Recall은 **상한이 과대평가**돼 있다
- Human Review는 **1인 판정**이다. 프로젝트 여건상 복수 판정자를 둘 수 없으므로 이 값은 **절대 정확도가 아니라 "한 판정자와의 합치도"**로만 읽어야 한다. 대신 v0.1·v0.2가 동일한 평가셋·동일 판정자·동일 지표 정의를 공유하므로 **두 버전의 차이(delta)는 유효**하다
- v0.1은 후보 68건의 강도를 기록하지 않아 Dataset v0.1 값을 대용했다. 강도를 엄밀히 비교할 수 있는 구간은 신규발견 43건뿐이다(그 구간만 보면 57.7% → 83.3%)

### 규칙으로는 더 줄지 않는 오차

남은 오탐 27건은 v0.2 기준으로는 명백한 신호인데 사람은 아니라고 봤다. 프롬프트 결함이라기보다 **사람의 기준선이 "복습 우선순위 판단에 실제로 유용한가"로 훨씬 좁다**는 신호다. 다음 버전은 규칙을 더 넣을 게 아니라 **판정 기준 자체를 사람과 맞추는 작업**이 먼저다.

### 아직 열려 있는 게이트

H-Signal은 게이트 1번일 뿐이다.

| 게이트 | 검증 설계 | 상태 |
|---|---|---|
| **H-Signal** — 신호 밀도 | 임계 ≥ 2.0회/h | 🟢 **통과** (보수적 분모 8.7회/h) |
| **H-Trust** — 신뢰·행동 변경 | 20명 Wizard of Oz 블라인드 A/B · 1주 | 🔴 미실행 |
| **H-Conv** — 유료 전환 3% | 랜딩·프로토타입 전환율 | 🔴 미실행 |
| **H-B2B** — 기관 예산 배정 | 훈련기관 5곳 인터뷰 | 🔴 미실행 |

### 게이트로 해소되지 않는 충돌

부록 A는 가치 B가 성립하더라도 **범용 AI 사정권 안**이라고 본다. 이 충돌은 신호 밀도 실험으로 답할 수 없다. H-Signal 문서에도 다음을 명시해 두었다.

> 신호가 존재해도 **범용 AI가 같은 것을 하는지**는 답하지 않는다.

### 다음 실험 우선순위

1. **다른 강사 · 다른 과정의 STT로 신호 밀도 재측정** — 현재 결과는 표본 1인에 묶여 있다
2. **판정 기준서 작성 + 시간차 자가 재판정** — 복수 판정자는 여건상 불가하므로, 27건 기각 사유를 코딩해 기준서로 명문화한 뒤 일정 기간을 두고 같은 셋을 다시 판정해 **자기 일치도(intra-rater)**를 측정한다. 1인 체제에서 판정 안정성을 확인할 수 있는 방법이다
3. **v0.2의 과소 편향과 도입부 과잉 억제 수정** — 원인은 이미 진단됐다 (강도 승격 조건 ①을 너무 좁게 읽음 · TOPIC_INTRO 규칙이 개념 도입과 요건 진술이 겹친 발화를 기각)
4. **H-Trust (20명 A/B)** — 신호가 있다는 것과 학습자가 그 순서를 채택한다는 것은 다른 문제다
